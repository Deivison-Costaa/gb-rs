# Iteração 0071 — MBC5

- **Data:** 2026-07-27
- **Item do roadmap:** 5.3

## Objetivo

Implementar o MBC5: ROM banking de 9 bits (dois registradores em `$2000`–`$2FFF` e `$3000`–`$3FFF`), RAM banking de 4 bits (até 16 bancos de 8 KiB via `$4000`–`$5FFF`), 6 tipos de cartucho (`$19`–`$1E`) despachados em `load()`. Rumble ignorado. Banco 0 é banco 0 (divergência de todos os MBCs anteriores).

Achado da bateria: o teste `rom_bank_register_low_is_8_bits` original sobreviveu a M2 (máscara de 7 bits) porque `rom_byte(128, addr)` = `rom_byte(0, addr)` na aritmética de `u8` — `(128u8 << 4)` = 0x00. Reescrevi o teste com fixture customizado que grava `bank as u8` no offset `0x1000` de cada banco, eliminando a colisão.

## Decisões de arquitetura

Nenhuma nova. O `Mbc5` segue o mesmo padrão de `Mbc3`: struct com `rom`/`ram` em `Box<[u8]>`, `Cartridge` trait, `with_battery()` builder, sem RTC.

## Notas

- O MBC5 fecha o marco M5 (Mappers). Os 6 tipos (`$19`–`$1E`) estão todos despachados.
- Rumble (bit 3 de `$4000`–`$5FFF` nos tipos `$1C`–`$1E`) é aceito como parte do registrador de RAM bank — sem hardware físico, o bit é tratado como seleção de banco normal.
- O `ram_bank` inicial é 0x00 (primeiro banco de RAM), consistente com a ausência de tradução 00→01 em todo o MBC5.
- O `rom_bank_low` inicial é 0x01, seguindo o comportamento de power-up de todos os MBCs (a região `$4000`–`$7FFF` começa no banco 1).
